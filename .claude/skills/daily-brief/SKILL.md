# Ежедневный брифинг: выборы и геополитика

Зачем (решение 04.11.2026, `docs/OPERATING_POLICY.md` §0.5, §2): сигналы бота
не обогнали рынок (40 рынков, +1пп при шуме ±8пп; реальные деньги −20%), а
весь плюс кошелька — собственные ставки оператора на выборы и геополитику.
Grok выключен. Раз в день оператор запускает этот разбор: ты приносишь
факты и свою оценку, **решение принимает оператор. Это не сигнал.**

Отвечай по-русски, время — по Москве. Не называй размер ставки и не пиши
«купить/продать» — пиши, где оценка расходится с рынком и почему.

**Два режима.** По просьбе оператора в чате — отчёт в чат и в канал. По
расписанию (запланированная сессия, оператора рядом нет) — только в канал:
ничего не спрашивай, решай по этой инструкции, доведи до пуша.

## 1. Подготовка

```bash
cd /home/user/Polymarket_insider    # или где клонирован BRKME/Polymarket_insider
git checkout main && git pull origin main
python3 -m pip install -q -r requirements.txt
```

**Право пуша — до разбора, не после.** Проверь: `git push --dry-run origin
HEAD:main` (код возврата отдельно). Сессия по расписанию часто стартует без
подключённого репозитория: клон читается, а пуш даёт 403. Тогда вызови
инструмент `mcp__claude-code-remote__add_repo` с owner `BRKME`, repo
`Polymarket_insider`, access `push` (не видно инструмента — ToolSearch
«add_repo»), выполни команду клонирования из его ответа и
`register_repo_root`, если он о нём скажет, и работай в новом клоне.
Проверку повтори. Права пуша так и нет — разбор не начинай: напиши об
отказе в итоговом сообщении сессии, не выдавай частичную работу за сделанную.

## 2. Состояние

```bash
python3 briefing.py score      # как разбор работал до сих пор
python3 daily_status.py        # открытые позиции кошелька (Telegram в сессии не шлёт)
```

Строку `score` выведи первой строкой отчёта как есть. Пока зарезолвлено
меньше 30 разборов, добавь: «преимущество разбора над рынком не доказано».
Если Brier разбора хуже рынка на n ≥ 30 — скажи об этом прямо, первой фразой.

## 3. Очередь

```bash
python3 briefing.py queue      # --limit N, --json для полного вывода
```

Очередь — выборы и геополитика, YES 10-90¢, резолв через 1-60 дней,
ликвидность ≥ $25k, одна строка на событие; уже разобранное возвращается
только при сдвиге цены ≥15пп. Разбери до 5 рынков: сначала открытые позиции
оператора, затем ближайшие резолвы. Если очередь пуста — так и скажи, не
добирай рынки вручную ради объёма.

## 4. Разбор каждого рынка

1. **Прочитай правила резолва полностью** (поле «Правила»). Ловушки: источник
   истины, точная формулировка, досрочные триггеры («объявление» резолвит YES),
   связанные исходы. Сформулируй одной фразой, что именно решит исход.
2. **Найди факты поиском (WebSearch, WebFetch):** официальные результаты и
   заявления, опросы — с датой, источником и выборкой, график событий до
   резолва. Каждый факт — с датой. 3-5 самых важных и свежих.
3. **ЗАПРЕЩЕНО** брать как факт котировки рынков предсказаний и ставок —
   Polymarket, Kalshi, PredictIt, Manifold, букмекеры, «рынки оценивают в N%».
   Не ищи их и не пересказывай: оценку сверяют именно с ними, ссылка на них
   делает разбор бесполезным.
4. **Оценка P(YES) — следствие фактов, не цены.** Начни с базовой ставки для
   класса события, двигай под конкретные факты. Опросы — не исход: рынок по
   событию ближайших дней их уже учёл. Выше 85% или ниже 15% — только при
   фактах, делающих исход почти неизбежным. Мало фактов — держись ближе к
   середине и ставь conf low.
5. Только после оценки сравни с ценой рынка. Расхождение меньше 5пп —
   «согласен с рынком». Не подгоняй оценку под цену и не уводи от неё нарочно.

## 5. Запись в журнал — по КАЖДОМУ разобранному рынку

```bash
python3 briefing.py log --cid <cid> --my-yes 0.42 --conf medium --note "главный довод одной фразой"
```

Записывай и те, где ты согласен с рынком: журнал только с расхождениями
раздует результат (отбор по исходу — политика §4). `--my-yes` — доля 0..1.
Цена рынка подставляется автоматически на момент записи. Команда печатает
строку `🚦 …` — вердикт по этому рынку; перенеси её в отчёт как есть (без
`🚦 `), не переписывай своими словами. Правило одно для всех дней:
⚪ ПРОПУСТИТЬ — расхождение <5пп; 🟡 НАБЛЮДАТЬ — 5-10пп или conf low;
🟢 ПРИСМОТРЕТЬСЯ — ≥10пп при conf medium/high.

## 6. Отчёт оператору — два файла (дата по Москве)

Оператор 05.11: «сообщения не читаемые, достаточно 1-2 предложений для
обоснования, а не вся новость целиком». Поэтому:

**research/brief_notes/ГГГГ-ММ-ДД.md — полный разбор, в канал НЕ уходит.**
По каждому рынку: что решит исход по правилам, факты с датами и
источниками, ближайшие события, риски, оценка и conf. Это архив для
проверки разбора задним числом — пиши его полностью.

**research/briefs/ГГГГ-ММ-ДД.md — то, что уходит в канал. Коротко.**

```
<строка score>
<одна фраза: есть ли сегодня на что смотреть>

<ВЕРДИКТ> — <короткое имя рынка по-русски> · <остаток строки вердикта>
Почему: <1-2 предложения: главный факт с датой → вывод>
Резолв <ДД.ММ> · <ссылка на рынок>

…следующий рынок так же…

Это не сигнал — решение за тобой.
```

- `<ВЕРДИКТ> · <остаток>` — строка `🚦 …` из `briefing.py log` как есть:
  первое слово (⚪ ПРОПУСТИТЬ / 🟡 НАБЛЮДАТЬ / 🟢 ПРИСМОТРЕТЬСЯ) ставит код, не
  ты. Короткое имя вставь после слова через « — ».
- «Почему» — не больше двух предложений и ~200 символов: один решающий факт
  и вывод. Списки фактов, источники, «Ближайшее», «Риски» — только в
  brief_notes.
- Рынки — в порядке: 🟢, затем 🟡, затем ⚪.
- В канале — только вероятности в процентах («рынок 55%»), никаких центов
  (оператор 05.11: «желательно видеть вероятности в %, а не 55 центов»).
  Цена YES в ¢ и вероятность рынка — одно и то же число.
- Блока «Итог» нет: три строки на рынок и так читаются за секунды.

Пример:

```
🟡 НАБЛЮДАТЬ — Перемирие Россия–Украина · рынок 14% · разбор 8% · перекос к NO · если разбор прав +8%
Почему: в Абу-Даби 10-11.11 встреча рабочего уровня, Путин публично против короткого перемирия — общей паузы до 31.12 не видно.
Резолв 31.12 · https://polymarket.com/event/russia-x-ukraine-ceasefire-agreement-by
```

Файл уходит в Telegram простым текстом: без markdown-разметки (никаких `**`,
`#`, обратных кавычек), эмодзи можно. Без размера ставки, без «купить».
Очередь пуста — всё равно напиши короткий файл: строка score и «новых
рынков по выборам и геополитике нет», чтобы канал знал, что разбор прошёл.

## 7. Публикация

```bash
git add research/brief_log.jsonl research/briefs/ research/brief_notes/
git commit -m "brief: разбор DD.MM"   # + строки атрибуции сессии; БЕЗ [skip ci]
git push origin HEAD:main
```

Пуш файла брифинга запускает воркфлоу `brief_send.yml` — он и шлёт брифинг
в канал (токен бота есть только в секретах Actions). Метка `[skip ci]` в
сообщении коммита отменит отправку. Код возврата проверяй отдельно, не
через пайп. Отклонён пуш (гонка с ботами) — `git pull --rebase origin main`
и пуш снова. Второй разбор за день — новый файл
`ГГГГ-ММ-ДД-2.md`: изменённый файл воркфлоу отправит целиком ещё раз.

Если оператор держит позицию по рынку из разбора — отметь это и скажи,
изменились ли факты с момента входа.
